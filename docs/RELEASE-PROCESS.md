# Releasing a Mac and web update

1. Review the branch inventory, patch differences and selected source. Build a clean, single-root release snapshot. Keep the published stable release available as the upgrade baseline.
2. On Apple Silicon, run [the local build and validation](LOCAL-BUILD.md). Require matching case inventories and zero skipped, failed or flaky cases across Chromium, Firefox and WebKit. Check the packaged Mac app and upgrade an isolated profile using the published baseline. Confirm the manifest records the correct source and a clean tree.
3. Create a private staging repository with Actions disabled. Push the root commit on main and an annotated tag pointing to it. Create an empty draft release. Use scripts/verify-release.py with the candidate tag, Mac release directory and native evidence directory. First verify locally, then use --upload-draft with the staging repository and baseline repository. Check the ZIP, mounted DMG, executable, app.asar, manifest, checksums and all four remote assets.
4. Inventory the current repositories and obtain the owner's approval before replacing the official snapshot. Keep the old repository available under a temporary name until verification finishes. Rename the staging repository and run --verify-draft under the official name. Publish the stable release, make the repository public, and use --verify-remote to check the latest release, refs and every asset. Recheck anonymous downloads before removing obsolete copies.
5. Deploy the static dist directory built from the same source. Verify anonymous access, the shipped assets, language selection, mobile layout and JSON import/export. Store build and deployment evidence outside Git.
