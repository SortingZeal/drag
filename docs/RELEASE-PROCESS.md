# Releasing the desktop apps and updating the web test site

1. Review the branch inventory, patch differences and selected source. Build a clean, single-root release snapshot. Keep the published stable release available as the upgrade baseline.
2. On Apple Silicon, run [the local build and validation](LOCAL-BUILD.md). Require matching case inventories and zero skipped, failed or flaky cases across Chromium, Firefox and WebKit. Check the packaged Mac app and upgrade an isolated profile using the published baseline. Confirm the manifest records the correct source and a clean tree.
3. Build the Windows x64 executable from the same commit and verify that it launches on Windows with an isolated profile. Check its manifest and the version and contents of the bundled editor. Create a private staging repository with Actions disabled. Push the root commit on main and an annotated tag pointing to it. Create an empty draft release. Use scripts/verify-release.py with the candidate tag, Mac release directory, native evidence directory and --windows-dir pointing at the Windows executable and manifest. First verify locally, then use --upload-draft with the staging repository and baseline repository. Check the ZIP, mounted DMG, executable, app.asar, manifest, checksums and every remote asset.
4. Inventory the current repositories and obtain the owner's approval before replacing the official snapshot. Keep the old repository available under a temporary name until verification finishes. Rename the staging repository and run --verify-draft under the official name. Publish the stable release, make the repository public, and use --verify-remote to check the latest release, refs and every asset. Recheck anonymous downloads before removing obsolete copies.
5. Deploy the build from the same editor source to the existing web test site. Verify anonymous access, the shipped assets, language selection, mobile layout and JSON import/export. Store build and deployment evidence outside Git.
